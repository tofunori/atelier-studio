# assistant-ui — couverture des éléments Atelier

Audit réalisé le **2026-09-10**. Le catalogue contient **143 éléments** : 121 entrées explicites du registre et 22 templates génératifs. La liste a été vérifiée dans le snapshot local assistant-ui au commit `1a5da0f272668cf313e5213e49aa70e0f987de6d` (`apps/docs/components/pages/elements/registry.tsx` et `apps/docs/lib/gallery-templates.ts`), puis contre la documentation publiée par Firecrawl : [catalogue Elements](https://www.assistant-ui.com/elements) (scrape `01a08b26-dbca-772d-8da5-546ce922e837`) et [Reasoning effort](https://www.assistant-ui.com/elements/reasoning-effort) (scrape `01a08b26-df15-713c-bbcc-50ce96fe8d54`).

Le statut **Importé** signifie que la source officielle existe sous `src/components/assistant-ui/**` et qu’elle est utilisée par le host ou le bench. **Présent via source officielle** désigne une capacité déjà fournie par `Thread` (composer, viewport, actions), sans créer une copie standalone. **Partiel** signifie qu’une partie du contrat est raccordée. Les lignes **Source staged** disposent maintenant aussi de la source upstream complète dans [`src/components/assistant-ui/catalogue`](../src/components/assistant-ui/catalogue), avec le suffixe `.source` pour empêcher tout chargement implicite ; elles restent non montées tant que leurs données, callbacks ou dépendances ne sont pas réels. Les lignes **Non importé** restantes sont les templates provider/toolkit qui n’ont pas de composant autonome à copier.

`reasoning-effort` est une entrée officielle installable (`npx shadcn@latest add "@assistant-ui/elements-reasoning-effort"`). La sélection d’effort (`config.reasoningEffort`) et la consommation du budget sont deux flux distincts : Atelier expose la sélection dans le picker/bench, mais ne branche pas encore `useThreadTokenUsage` (ou équivalent provider) pour `spent` dans le chat de production.

Les sources copiées/adaptées conservent l’attribution MIT assistant-ui décrite dans [`src/components/assistant-ui/README.md`](../src/components/assistant-ui/README.md). Les adaptations se limitent aux alias `tw:`/Base UI, à l’isolation CSS et aux slots explicitement listés; aucun primitive shadcn existant n’est remplacé. Les feuilles de support `ReasoningPanel` et `ComposerContext` viennent du même snapshot officiel; `ActivityGraph` est maintenant présent dans le staging upstream, mais reste non monté tant que sa dépendance `heat-graph` n’est pas installée et qu’aucune série d’activité ne peut être fournie.

Les 113 feuilles officielles qui n’étaient pas encore adaptées sont archivées byte-for-byte dans le [manifest de staging](../src/components/assistant-ui/catalogue/manifest.json). Le manifest conserve les imports externes (MCP, generative-ui, Shiki, heat-graph, etc.) afin de préparer une installation ciblée plutôt qu’une dépendance globale. La galerie peut référencer ces sources comme « staged / simulated » ; le chat de production ne les affiche pas sans payload et callback correspondants.

### Raccordement du raisonnement — 2026-09-10

La [documentation officielle](https://www.assistant-ui.com/docs/primitives/chain-of-thought)
recommande `MessagePrimitive.GroupedParts`, déjà utilisé par Thread. Les signaux
`thinking`, `thinking_live`, `thinking_delta`, `thinking_progress` et les sentinelles
`__thinking`/`__thinking-step` alimentent désormais des parties natives `reasoning`.
Leurs marqueurs restent des métadonnées : ils ne deviennent jamais du texte de modèle.
Une phase sans texte utilise `unstable_summary` pour son libellé d’état, car le
convertisseur officiel `fromThreadMessageLike` filtre sinon les parties vides.
Les phases sans contenu sont retirées de l’affichage une fois terminées ; les textes
fournis restent consultables, dans l’ordre des outils et des réponses. Chaque phase
porte son statut explicite. Le renderer Atelier `atelier-reasoning-signal` est retiré.
Le point générique officiel reste disponible lorsqu’aucun signal de réflexion n’est fourni.


### Conversation Map et effort — raccordement de production

Les deux sources officielles Conversation Map sont montées dans Thread (préfixe
Tailwind `tw`, imports locaux, compatibilité ES et portée du portail uniquement).
Le sélecteur Reasoning Effort reçoit les niveaux annoncés par le fournisseur et
partage l’état utilisé à l’envoi. Ses champs `budget`/`spent` acceptent l’absence
de données : aucun zéro ni plafond arbitraire n’est présenté comme mesure réelle.
L’état indisponible est une adaptation explicite du composant officiel, nécessaire
au transport CLI actuel ; aucun compteur temps-réel n’est revendiqué.
