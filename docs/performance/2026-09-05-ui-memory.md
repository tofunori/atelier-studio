## Reproduire les mesures

Depuis ce checkout, avec son app buildée ouverte :

```sh
node scripts/sample-memory.mjs /tmp/atelier-memory.jsonl repos
node scripts/sample-memory.mjs /tmp/atelier-memory.jsonl pdf-ouvert
node scripts/sample-memory.mjs /tmp/atelier-memory.jsonl panneau-ferme
```

Répéter les mêmes ouvertures/fermetures avec le même document et laisser un temps
de repos entre les cycles. Pour une session prolongée, reprendre les mesures à
intervalles réguliers avec les mêmes panneaux ouverts. Éviter les builds et tests
pendant la mesure. Comparer les PID et l'âge des processus : un redémarrage ne
constitue pas une récupération de mémoire du même processus.

Le script enregistre la RSS en Kio, pas l'empreinte physique de macOS. Les pages
partagées peuvent être comptées plusieurs fois et la compression influence la RSS.
Les processus WebKit hors de l'arbre Atelier restent explicitement non attribués ;
leur somme n'est pas présentée comme la mémoire de l'app. Les arguments des
processus ne sont pas collectés (`ps comm=`).

Les premières mesures exploratoires avant rebuild sont perturbées par un processus
fournisseur temporaire et par les tests : elles ne permettent pas d'estimer une fuite.
Les files Rust sans limite repérées dans send.rs et codex_rpc.rs restent un point
à instrumenter sous charge ; aucune fuite de ces files n'a été démontrée ici.
