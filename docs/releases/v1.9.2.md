# Atelier Studio 1.9.2

Atelier Studio 1.9.2 is a wide release. Free discussions become managed
workspaces with a permanent Markdown draft. A review workflow lands in the Rust
runtime, in the chat and on mobile. LaTeX review decisions leave the floating
card for a row under each changed passage and are now remembered by the server.
The figure viewer has a single toolbar, reading mode gets its own chat overlay,
and the last Node runtime leaves the repository. Pasted text is archived with
its content again, its preview is redesigned, and a background polling leak is
closed. 1.9.1 was never tagged; this release follows 1.9.0 directly.

## Free discussions become managed workspaces

- A chat without a project now owns a managed workspace under Application
  Support, addressed by a stable UUID. A permanent Markdown draft is prepared
  automatically and opened in the document tabs, and the agent is told where it
  lives on every turn, including resumed sessions; nothing needs to be created
  by hand and no temporary copies are made.
- Existing free chats migrate to a managed workspace when selected. The
  migration waits while a native turn is running, retries on the next idle
  snapshot, and a composer submission that triggered it is replayed against
  the new root so the prompt and attachments are not lost.
- Knowledge-base and instruction selections pending from a previous project are
  not copied into a new discussion; the discussion starts with only its own
  attachments.
- The rail gains a Discussions entry, favourite chats and sealed chats. The
  main window restores the active project but always opens on the Chat panel.

## Review

- A review module joins the Rust runtime and the store: reviews are requested,
  journaled and returned through Atelier protocol envelopes rather than ad hoc
  messages. Providers expose an isolated structured review, distinct from
  Codex's native review, with an audit fixture for the A2 benchmark.
- The chat surfaces reviews through a dedicated hook and timeline entries; the
  auto-review setting travels with every send and with queued follow-ups.
- Native mobile gets a document review session and an inline review view.

## LaTeX review, anchored and durable

- Keep and Ignore moved out of the floating card onto the passage they govern:
  a row under the last changed line of each passage with ✕ and ✓ alone, the
  current passage in accent and the others dimmed. A grey rail marks the visual
  rows of each change, computed from coordinates so it stays exact inside a
  wrapped paragraph. ⌥↑ / ⌥↓ move between passages, ⌥↩ / ⌥⌫ decide the current
  one, and clicking or selecting inside a passage makes it current. Undo is a
  toast in the editor pane for eight seconds.
- Changed words inside a line read as solid pills with a gap between the old
  and the new word; strikethrough and underline are gone. The inline label
  states the line range only, not a fragment count.
- Decisions are persisted by the gallery server as a `review` operation in the
  intervention journal, rebuilt on load, with the server as the source of
  truth. They used to live in WebView localStorage, which the app does not keep
  across restarts, so accepted diffs reappeared after every relaunch. An
  intervention whose last pass is decided leaves the history and the counter
  follows; when none remain, Diff closes.
- Accept all on 189 interventions no longer fails with 413: the client sends
  only texts the server does not already hold, and the `/versions` route
  accepts bodies up to 8 MB, matching its announced limit.
- Agent edits merge into a dirty buffer through a three-way merge and appear
  immediately as an `external-merge` intervention. The previous "when clean"
  policy ignored the disk until the next compile, which then discarded local
  typing. A conflict is raised only when the two deltas overlap.
- Diff mode shows the full selection capsule: Add to chat with the diff
  context, Annotate and Quick Ask. Under 460 px the LaTeX toolbar drops its
  whole-file Add to chat button to keep a single row; the capsule keeps it.
- LaTeX highlights and comments travel to the chat, and the compiled PDF
  refreshes in place after a build.

## Reading and annotations

- Reading mode gets a chat overlay: a floating composer over the reading view,
  a queue of pending annotations, and the latest reply behind a disclosure.
- Annotations sent from a PDF or an editor render as cards in the user bubble:
  the source with its location, opening the file at the line or page, the quoted
  passage (collapsible when long) and the comment set apart from the prompt.
- Annotation badges sit on the passage they mark rather than at column zero,
  and stack when two land on the same row.
- The chat's status banner is replaced by an alert icon in the header. The
  message opens on demand; an uncertain delivery after a restart offers "Check
  status" and never resends the message.

## Chat

- Pasted text is archived with its content. The archived user bubble kept only
  a name and a line count, so the "Pasted text" chip of a restored thread opened
  nothing. Pastes made before this release keep an inert chip; new ones open.
- The paste preview is redesigned without controls: the box picks its reading
  from the content. Source (monospace, line numbers, hard breaks respected) for
  LaTeX, Markdown and code; Text (paragraphs rejoined, the thread's typography)
  for prose, including prose hard-wrapped by a PDF. The header carries the name,
  a short meta ("10 lines · LaTeX", "2 paragraphs · 96 words") and two icon
  buttons; Copy shows a check for a second. The chip reads "10 lines" instead of
  "(lines 10)".
- Sub-agents: the inline group is a disclosure with one row per agent and its
  current activity, and a detail panel with the child transcript. Polling of
  child transcripts stops when the parent turn ends, even when a child's own
  completion was missed; it used to keep a 2.5 s timer alive indefinitely. A
  Codex fork carries the turn it branches from.
- Codex: resuming long sessions is hardened; a provider now awaits the durable
  Atelier binding before starting native work. A transient goal read no longer
  fails the turn; the status line says "awaiting model" or "connection
  uncertain" from the supervision signal instead.
- Display-math fences glued to their content (`\end{pmatrix}$$`,
  `$$\begin{pmatrix}`) are put on their own line before parsing, so KaTeX no
  longer renders the source in red or drops the first line.
- Removing an attachment no longer leaves an "… removed. Undo" line in the
  prompt box.
- The instruction assistant passes an explicit rewrite mode (correct, clarify,
  shorten, structure, questions, custom) instead of encoding it in the
  description, so the provider applies a policy per action.
- Grok and Kimi history and send paths were adjusted.

## Composer, rail and editors

- UI primitives settle on Base UI; the Radix migration is reduced to what the
  app uses. The rail's Automations and Highlights live under a "More actions"
  menu, Settings opens a menu with Settings and Usage, and the pane tab menu
  moves its three growing lists (tabs, panes, colours) into submenus.
- LaTeX and code editors get an "Add to chat" button in their toolbar, sending
  the file's absolute path so the agent reads the disk version.
- The bibliography gains Zotero collections and tabs.

## Gallery

- The figure viewer has one 44 px toolbar: ⓘ · ‹ n/N › · zoom · annotate ·
  chat · ⋯ · ×. Everything that describes the file (name, folder, date, size,
  dimensions, provenance, open original, copy path) lives in a sheet under ⓘ;
  the name fades in for 1.5 s when the figure changes. Annotate is a pencil,
  the annotation tools stay visible in the bar and select the mode when
  clicked, fullscreen is back in the bar, and the "select" tool is gone —
  an existing annotation is grabbed by its number or its edge, leaving its
  area free to draw inside.
- The gallery opens on the main project only; "All folders" remains a menu
  choice and never overrides the user's selection.
- Figure versions and gallery favourites are served by the Rust gallery
  server, with end-to-end coverage. Markdown WYSIWYG selection is wired to the
  chat.

## Runtime and repository

- No Node runtime remains in the repository (plan 065 closed). The KB Node
  chain (`sidecar/`) and the Node gallery server are gone; their behaviour is
  frozen as fixtures, and the KB parity contract runs 114 steps against
  `atelier-kb-rs`. The historical Python gallery servers are removed. Test
  harnesses run on `atelier-gallery-server`, whose newest binary wins over a
  stale tracked dist.
- The .app bundles only `gallery/assets/`; sources, scripts and test artefacts
  no longer ship. The gallery diff suite, e2e suite (116/116) and the verify
  gate are green.
- Design contract: nude buttons replaced by the UI primitives, hard-coded
  colours and off-scale radii moved to tokens, elevated surfaces without
  borders, and the App test suite realigned on the current UI (icon-only Stop,
  alert popover, rail menus).
