# Atelier Studio 2.1.0

Atelier Studio 2.1.0 rassemble trois semaines de travail depuis la 2.0.0 :
des spécialistes délégués façon Claude Science, un noyau Python persistant par
fil, un éditeur Word (.docx) avec suivi des modifications, un éditeur visuel
LaTeX avec revue des modifications de l'agent, un lecteur PDF beaucoup plus
complet, et une grande passe de finition de l'interface. L'app iPhone native
progresse aussi (interface hybride, lecture continue, galerie), mais cette
release ne publie pas d'app iOS.

Cette release contient tout l'historique de `main` après **v2.0.0** jusqu'à
**9f15e2a0** (PR #26 à #101), plus la préparation décrite plus bas.

## Points forts

### Agents, spécialistes et calcul

- **Spécialistes** : fiches de spécialistes, import des fiches Claude Science,
  menu du fil et proposition par l'agent (#50) ; un fil ne branche que les
  connecteurs MCP (#57) et les skills (#74) de sa fiche ; délégation par
  `@Nom` (#74) ; mode de permission hérité, demandes visibles, noyau Python
  partagé (#86) ; le budget d'échanges se recharge quand l'utilisateur reprend
  la main (#94).
- **Noyau Python persistant par fil** (#55) : preuves et suivi de chaque calcul
  (#88), reprise d'un fil précédent, bouton Démarrer et cellule libre (#90),
  figures ouvertes en grand dans une visionneuse (#97).
- **Calculs lancés par l'agent** : carte Lancer / Refuser, suivi et fiches
  d'hôte (#56). **Recette exacte** de chaque fichier produit (#53).
- **Relecteur** : Claude et Codex savent relire un tour (#51).
- **Mémoire** : souvenirs de projet, import Claude Science, rappel dans le fil
  (#54).
- **Sous-agents** : grappe comme les actions (#61), qui suit le message de
  pilotage (#77), vue d'ensemble lue à la place du chat (#78), déroulé de
  nouveau visible (#79) ; panneau Agents limité aux spécialistes délégués
  actifs (#98).
- **Sélecteur d'effort** : jauge segmentée, transparence et animations (#93).

### Chat

- Rangées d'actions sur une grille fixe, phrase de Claude et sortie en direct
  (#60) ; fichiers modifiés alignés et diff sobre dans le fil (#59).
- Citations en filet sans phrase répétée, passage cité sélectionné dans le PDF
  (#47) ; recliquer ramène au passage, page décalée tolérée (#49).
- Une pilule `.html` ouvre la page rendue (#58) ; diagrammes Mermaid rendus par
  Pele (#52) ; une figure annotée n'affiche plus que sa carte (#87).
- Rail compact : signaux lisibles, boîte « À traiter », notifications réparées
  (#99) ; barre du haut épurée avec alerte en ligne (#80).

### Rédaction : LaTeX et Word

- **Éditeur Word (.docx)** : moteur Rust maison, suivi des modifications signé
  et outils MCP (#83).
- **Éditeur visuel LaTeX** façon Overleaf (#35) ; diff unifié et barre de revue
  pour les modifications de l'agent (#62), plus lisible (#37) et plus contrasté
  (#65).
- Compilation 0,8 s après ⌘S, l'aperçu ne recharge qu'un PDF complet (#36) ;
  Compiler en bouton plein (#73) ; défilement et sélection plus fluides (#34) ;
  un clic reste un clic (#41) ; plus de fond gris sur le paragraphe du curseur
  (#44).

### PDF, annotations et bibliothèque

- **Lecteur PDF** : barre d'outils complète (note, zone de texte, tampons,
  barré, plan, export) (#29) ; tampons et notes déplaçables (#30) ; la page et
  la barre ne glissent plus au défilement (#26) ; sélection fiable même quand
  la police annonce une hauteur nulle (#84).
- **Bulles d'annotation** : bulle « Fiche » et pastilles en anneau (#28) ;
  capsule de sélection unique (#31) ; bulle de note sur plusieurs lignes, mode
  « composer », largeur fixe (#42, #43, #72, #85).
- **Codage qualitatif** façon NVivo : livre de codes, bouton Coder, onglet
  Codes, outils MCP (#46).
- **Zotero** : un article ajouté apparaît sans recharger la Bibliothèque (#48).

### Galerie

- Une carte par figure, la visionneuse liste ses fichiers (#95) ; copies
  d'archives masquées par défaut avec un interrupteur « Archives » (#45).

### Interface

- Thème « Claude Code », clair et sombre, dans l'app, la galerie et l'éditeur
  (#40).
- Finitions : icônes, étiquettes, grille de 4, focus, infobulles (#32) ; lot 1,
  pannes visibles de l'app et de la galerie (#96) ; lot 2, défilement,
  lisibilité, contrôles, mouvement et sélection (#100).

### Fiabilité

- Un fichier illisible n'est plus jamais lu comme vide puis écrasé (#63).
- Un texte en cours n'est plus perdu : brouillon de secours et confirmation
  avant de fermer ou quitter (#69).
- Rien ne se détruit ni ne s'ouvre en silence (Plan, Restaurer, CLI muets, SVG,
  mémoire) (#67) ; journaux durables et relance réversible (#68).
- CI : E2E en deux moitiés parallèles (#38), `main` garde son verdict, `POST
  /versions` atomique, tests instables corrigés (#66, #89).

### App iPhone (sources seulement)

- Interface hybride, verre d'iOS 26 (#71) ; mode Lecture en lecture continue
  (#76) avec ligatures annotables et césures rejointes (#33) ; galerie avec le
  dossier sur chaque carte et copies archivées masquées (#91) ; envoi TestFlight
  scripté (#81).

### Distribution

- Les scripts de build locaux savent signer avec un certificat Developer ID et
  notariser le DMG (#70). Le workflow de release GitHub, lui, garde la
  signature ad hoc : l'artefact publié ici n'est pas notarisé.

## Compatibilité

L'artefact cible **macOS sur Apple Silicon (arm64)** et embarque le backend
Rust et le runtime de la galerie. Claude Code CLI et Codex CLI restent des
prérequis externes pour leurs fournisseurs. Le noyau Python demande un Python 3
local ; l'éditeur .docx et les spécialistes n'ont pas de dépendance
supplémentaire.
