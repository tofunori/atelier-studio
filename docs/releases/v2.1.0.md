# Atelier Studio 2.1.0

Atelier Studio 2.1.0 gathers three weeks of work since 2.0.0: delegated
specialists in the style of Claude Science, a persistent Python kernel per
thread, a Word (.docx) editor with tracked changes, a visual LaTeX editor with
review of the agent's edits, a much more complete PDF reader, and a broad
interface polish pass. The native iPhone app also moves forward (hybrid
interface, continuous reading, gallery), but this release does not publish an
iOS application.

This release contains the full `main` history after **v2.0.0** through
**dc9e10e6** (pull requests #26 to #102).

## Highlights

### Agents, specialists and computation

- **Specialists:** specialist profiles, import of Claude Science profiles,
  a thread menu and suggestions by the agent (#50); a thread only connects the
  MCP connectors (#57) and skills (#74) listed in its profile; delegation with
  `@Name` (#74); inherited permission mode, visible requests and a shared Python
  kernel (#86); the exchange budget refills when the user takes the turn back
  (#94).
- **Persistent Python kernel per thread** (#55): evidence and tracking for
  every computation (#88), resuming a previous thread, a Start button and a free
  cell (#90), figures opened full size in a viewer (#97).
- **Agent-launched computations:** Run / Decline card, tracking and host
  profiles (#56). **Exact recipe** for every produced file (#53).
- **Reviewer:** Claude and Codex can review a turn (#51).
- **Memory:** project memories, Claude Science import, recall in the thread
  (#54).
- **Subagents:** grouped like actions (#61), following the steering message
  (#77), an overview read in place of the chat (#78), their run visible again
  (#79); the Agents panel lists only active delegated specialists (#98).
- **Effort selector:** segmented gauge, transparency and animations (#93).

### Chat

- Action rows on a fixed grid, Claude's sentence and live output (#60);
  aligned changed files and a quiet diff in the thread (#59).
- Ruled citations without repeated sentences, with the cited passage selected
  in the PDF (#47); clicking again returns to the passage, and an off-by-one
  page is tolerated (#49).
- An `.html` pill opens the rendered page (#58); Mermaid diagrams rendered by
  Pele (#52); an annotated figure only shows its card (#87).
- Compact rail: readable signals, a "To handle" inbox, repaired notifications
  (#99); a cleaner top bar with an inline alert (#80).

### Writing: LaTeX and Word

- **Word (.docx) editor:** in-house Rust engine, signed tracked changes and MCP
  tools (#83).
- **Visual LaTeX editor** in the style of Overleaf (#35); unified diff and a
  review bar for the agent's edits (#62), easier to read (#37) and with
  stronger colors (#65).
- Compilation 0.8 s after ⌘S, and the preview only reloads a complete PDF
  (#36); Compile as a filled button (#73); smoother scrolling and selection
  (#34); a click stays a click (#41); no more grey background on the cursor
  paragraph (#44).

### PDF, annotations and library

- **PDF reader:** a complete toolbar (note, text box, stamps, strikethrough,
  outline, export) (#29); movable stamps and notes (#30); the page and toolbar
  no longer drift while scrolling (#26); reliable selection even when a font
  reports a zero height (#84).
- **Annotation bubbles:** "Card" bubble and ring-shaped swatches (#28); a
  single selection capsule (#31); multi-line note bubble, "composer" mode and
  fixed width (#42, #43, #72, #85).
- **Qualitative coding** in the style of NVivo: codebook, Code button, Codes
  tab, MCP tools (#46).
- **Zotero:** a newly added article appears without reloading the Library
  (#48).

### Gallery

- One card per figure, with the viewer listing its files (#95); archive copies
  hidden by default with an "Archives" switch (#45).

### Interface

- "Claude Code" theme, light and dark, across the app, gallery and editor
  (#40).
- Polish: icons, labels, 4-pixel grid, focus, tooltips (#32); batch 1, visible
  breakages in the app and gallery (#96); batch 2, scrolling, legibility,
  controls, motion and selection (#100).

### Reliability

- An unreadable file is never read as empty and then overwritten (#63).
- Text being typed is no longer lost: backup drafts and a confirmation before
  closing or quitting (#69).
- Nothing is destroyed or opened silently (Plan, Restore, silent CLIs, SVG,
  memory) (#67); durable logs and a reversible relaunch (#68).
- CI: gallery E2E split into two parallel halves (#38); `main` keeps its
  verdict, atomic `POST /versions`, flaky tests fixed (#66, #89).

### iPhone app (source only)

- Hybrid interface with iOS 26 glass (#71); continuous Reading mode (#76) with
  annotatable ligatures and rejoined hyphenation (#33); gallery showing each
  card's folder and hiding archived copies (#91); scripted TestFlight upload
  (#81).

### Distribution

- The local build scripts can sign with a Developer ID certificate and
  notarize the DMG (#70). The GitHub release workflow keeps its ad-hoc
  signature: the artifact published here is not notarized.

## Compatibility

The artifact targets **macOS on Apple Silicon (arm64)** and bundles the Rust
backend and the gallery runtime. Claude Code CLI and Codex CLI remain external
prerequisites for their providers. The Python kernel needs a local Python 3;
the .docx editor and the specialists have no additional dependency.
