# Atelier Studio 1.9.3

Atelier Studio 1.9.3 is a performance release for the chat. While a reply
streams in, the app no longer re-renders the whole window for every text
fragment: the streaming bubble reads a live channel of its own, finished turns
keep their view models, and the typewriter ticks on a timer instead of the
display's refresh rate. Measured on a real 2,108-event thread, the JavaScript
cost of a 20-second reply drops by 70 % in Chromium, and the WebKit content
process drops from 59 % to 30 % of a core. The cost no longer grows with the
length of the thread. A reproducible benchmark ships with the repository so the
next round is measured rather than guessed.

## Streaming no longer re-renders the screen

- Every text delta used to update `lastEventAt`, a piece of `App` state, so the
  entire window re-rendered twenty times a second; the same value sat in the
  virtual list's extra data and forced every visible row (Base UI buttons,
  timestamps, user bubbles) to render again, although no row read it. The
  value is a ref now and the dead prop is gone.
- Turn view models are cached per turn: a finished turn whose events and
  positions have not moved returns the same object; only the live turn is
  recomputed.
- The event store keeps a committed snapshot for the timeline that changes only
  on a structural change. A delta that merely grows the last streaming or
  thinking bubble notifies only the live subscribers of that thread; `Chat`,
  the turn projection and the virtual list keep their snapshot, and the bubble
  reads its text through the live channel.
- The typewriter runs on a 40 ms timer rather than `requestAnimationFrame`. It
  published at 25 Hz already; at 120 Hz on ProMotion displays four frames out
  of five did nothing but cost WebKit a full rendering update. A word and the
  space that follows it now reveal in one step instead of two publications,
  and the 40 ms cadence also applies when the target is reached mid-turn; the
  end of a turn still publishes without waiting. The network coalescer emits at
  most once every 30 ms for paced deltas.
- Kept by decision: the 40 ms cadence, the per-word fade and the smooth
  follow-to-bottom. Measurements did not justify touching scrolling or the
  virtual list.

## Benchmarks

- `scripts/bench/chat_stream_bench.mjs` loads the built app in Chromium or
  WebKit (Playwright) with Tauri stubbed and the chat server simulated, loads a
  synthetic or captured thread, streams a reply at a provider's pace, and
  reports CDP metrics, a sampled CPU profile, an aggregated rendering trace,
  page counters and CPU per process role, with streaming and finalization
  measured separately. Page probes are opt-in because they cost as much as
  what they measure; a guard refuses to run beside an orphaned bench browser.
- `scripts/bench/md_pipeline_bench.mjs` isolates the Markdown pipeline of the
  live block in the system JavaScriptCore and in V8: 0.21 ms per publication
  in JSC, 0.5 % of a core at 25 publications per second — parsing is not a
  lever; the remaining cost of the live block is its rendering.

## Notes

- About twelve points of WebKit content-process time during streaming remain
  unattributed by ablation. The next step is a Safari Web Inspector timeline
  recording of a real reply.
- No change to the backend or to the bundle size.
