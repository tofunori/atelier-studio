### Task 1: Allocateur de séquences partagé (bug de correction)

Deux écritures concurrentes ⇒ même séquence ⇒ ordre de `materialize` corrompu.

**Files:**
- Modify: `rust/crates/atelier-store/src/journal.rs` (+ tests dans le module)
- Modify: les trois sites d'appel ci-dessus

**Interfaces:**
- Produces: `Journal::next_sequence(&self, thread_id: &str) -> u64` — atomique, dense, initialisé paresseusement depuis le fichier.

- [ ] **Step 1: Inventaire préalable.** `grep -rn "last_sequence" rust/crates` — confirmer les trois sites et vérifier qu'ils passent tous par LA MÊME instance de `Journal` (`state.journal()` ou équivalent — si des instances distinctes existent pour le même dossier, STOP et rapporter BLOCKED avec preuve : un compteur en mémoire ne synchronise que ce qui partage l'instance).

- [ ] **Step 2: Test qui échoue (course).**

```rust
    #[tokio::test]
    async fn next_sequence_is_dense_under_concurrency() {
        let dir = tempfile::tempdir().unwrap();
        let journal = std::sync::Arc::new(journal_for_test(dir.path())); // adapter au constructeur réel
        let mut handles = Vec::new();
        for _ in 0..8 {
            let j = journal.clone();
            handles.push(tokio::spawn(async move {
                (0..50).map(|_| j.next_sequence("t1")).collect::<Vec<u64>>()
            }));
        }
        let mut all: Vec<u64> = Vec::new();
        for h in handles { all.extend(h.await.unwrap()); }
        all.sort_unstable();
        let expected: Vec<u64> = (1..=400).collect();
        assert_eq!(all, expected, "les séquences doivent être uniques et denses");
    }
```

(Adapter la base : si `last_sequence` d'un journal vide vaut 0, la première allocation vaut 1.)

- [ ] **Step 3: Implémenter.** Dans `Journal` : `sequence_counters: Mutex<HashMap<String, u64>>` (std::sync::Mutex — sections critiques courtes, pas d'await sous le lock). `next_sequence` : lock ; `entry(thread_id)` absent → initialiser via `last_sequence(thread_id)` (la lecture fichier existante, UNE fois) ; incrémenter ; retourner. Commentaire : trois écrivains concurrents, course vécue (revue finale 2026-08-28).

- [ ] **Step 4: Migrer les trois sites.** Chaque `let sequence = ...last_sequence(x) + 1;` devient `let sequence = ...next_sequence(x);`. AUCUN autre changement de comportement. Vérifier qu'aucun site n'écrit une séquence calculée autrement (`grep -n "\"sequence\"" rust/crates/atelier-runtime/src -r`).

- [ ] **Step 5: Suites** — `cargo test -p atelier-store -p atelier-runtime` puis workspace. Commit : `fix(store): allocateur de séquences partagé — trois écrivains concurrents ne peuvent plus entrer en collision`.
